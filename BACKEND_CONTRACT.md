# العقد مع الباك إند

كل رابط الواجهة بتحتاجه من لارافيل، مرتب حسب الوحدات. الفرونت مبني على هالعقد، ولحد ما يجهز الباك إند في سيرفر وهمي بيرد بنفس الشكل بالضبط.

لما نخلص الفرونت، هاد الملف هو قائمة الشغل للباك إند.

## قواعد عامة

- **الدخول:** بالكوكيز عن طريق Sanctum بوضع التطبيقات، مش بالتوكن. ولازم يكون في إعداد للنطاقات المسموحة ولمشاركة الكوكيز.
- **شكل الرد:** أي كائن أو قائمة بيكون جوا `data`، زي ما بترجع موارد لارافيل.
- **أخطاء النموذج:** حالة 422، ومعها `message` و`errors` مرتبة حسب الحقل.
- **الجلسة منتهية:** حالة 401 أو 419.
- **الصيدلية:** أي بيانات بترجع لازم تكون من صيدلية المستخدم بس. الفلترة حسب الصيدلية بتصير بالسيرفر دايماً.
- **الصلاحيات:** السيرفر بيفحص الدور بكل رابط، حتى لو الواجهة مخبية الزر.

## الوحدة 1: الدخول والبداية

### الدخول والخروج

| الطريقة | الرابط        | الطلب                                          | الرد                        |
| ------- | ------------- | ---------------------------------------------- | --------------------------- |
| POST    | `/api/login`  | `login` (جوال أو بريد)، `password`، `remember` | 200 والمستخدم مثل `/api/me` |
| POST    | `/api/logout` |                                                | 204                         |

لما يكون الجوال أو كلمة المرور غلط: 422، و`errors.login = ["credentials"]`، ومعها `attemptsLeft` (عدد المحاولات الباقية).

بعد 5 محاولات غلط: 429 ومعها `retryAfterMinutes: 15`.

المستخدم ممكن يكون صاحبة المنصة، وهي ما إلها صيدلية:

```json
{ "data": { "id": 100, "name": "رزان بلاطة", "phone": "0590000000", "role": "platform_owner" } }
```

المستخدم العادي صار فيه حقل جديد بالصيدلية: `onboardingDone`. بيكون `false` لحد ما المديرة تخلص قائمة البداية أو تخفيها.

### نسيت كلمة المرور

| الطريقة | الرابط                 | الطلب                                    | الرد                                                                      |
| ------- | ---------------------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| POST    | `/api/password/otp`    | `login`، `channel` (`whatsapp` أو `sms`) | 202، `{ "data": { "last": "307", "resendInSeconds": 45 } }`               |
| POST    | `/api/password/verify` | `login`، `code` (6 أرقام)                | `{ "data": { "resetToken": "..." } }` أو 422 و`errors.code = ["invalid"]` |
| POST    | `/api/password/reset`  | `resetToken`، `password`                 | 204، وبيطلع كل الأجهزة التانية من الحساب                                  |

**مهم:** رابط إرسال الكود بيرجع نفس الرد سواء الرقم مسجل أو لا، عشان ما حدا يقدر يفحص مين عنده حساب. الكود صالح 10 دقايق.

### طلب الانضمام والتفعيل

| GET     | `/api/activation/{token}`        |                                                                                       | `{ "data": { "pharmacyName", "ownerName", "phone" } }`، أو 410 لو انتهى، أو 404 لو مش موجود |

- التجربة المجانية (30 يوم) بتبلش من لحظة التفعيل.

## الوحدة 2: الموظفين والسجل والإعدادات

كل روابط هالوحدة للمديرة بس. الواجهة بتخفي الشاشات عن باقي الأدوار، بس السيرفر لازم يرفض بـ 403 كمان.

### الموظفين

| الطريقة | الرابط                           | الطلب                                                                    | الرد                                         |
| ------- | -------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| GET     | `/api/staff`                     |                                                                          | قائمة الموظفين، والمالكة أولهم               |
| POST    | `/api/staff`                     | `name`، `phone`، `email` اختياري، `role`، `discountLimit`، `permissions` | 201، بيانات الموظف ومعها `temporaryPassword` |
| PUT     | `/api/staff/{id}`                | نفس حقول الإضافة                                                         | الموظف بعد الحفظ                             |
| PATCH   | `/api/staff/{id}/status`         | `active`: true أو false                                                  | الموظف بعد التغيير                           |
| POST    | `/api/staff/{id}/reset-password` |                                                                          | `{ "data": { "temporaryPassword": "..." } }` |

- الدور بيكون `pharmacist` أو `cashier` بس. المديرة وحدة وهي المالكة.
- المالكة (`isOwner = true`) ما بتنعدل ولا بتنوقف من هون: 403.
- الموظف ما بينحذف أبداً، بينوقف بس، عشان فواتيره وسجله يضلوا.
- الموظف الموقوف ما بيقدر يدخل، وأي جلسة مفتوحة إله بتنقفل.
- لو الرقم مستخدم: 422 و`errors.phone = ["taken"]`.
- كلمة المرور المؤقتة بترجع مرة وحدة بس، والسيرفر ما بيخزنها إلا مشفرة. أول ما الموظف يدخل فيها لازم يغيرها.
- صلاحية `approveCounts` للصيدلاني بس. لو انبعتت لكاشير، السيرفر بيتجاهلها.

شكل الموظف:

```json
{
  "id": 2,
  "name": "سارة خليل",
  "phone": "0598210774",
  "email": null,
  "role": "pharmacist",
  "discountLimit": 10,
  "permissions": { "sellOnCredit": true, "seePurchasePrice": true, "approveCounts": true },
  "active": true,
  "isOwner": false,
  "lastLoginAt": "2026-11-24T06:12:00Z"
}
```

`discountLimit` نسبة مئوية، و`null` للمالكة يعني بدون حد.

### سجل النشاط

| الطريقة | الرابط          | الطلب (بالرابط)                                                                   | الرد         |
| ------- | --------------- | --------------------------------------------------------------------------------- | ------------ |
| GET     | `/api/activity` | `period` (`today` أو `week` أو `month`)، `actor`، `kind`، `sensitive=1`، `search` | قائمة الأسطر |

- السجل للقراءة بس. ولا حد بيقدر يعدله أو يمسحه، ولا المديرة.
- السيرفر هو اللي بيكتب السطر لما يصير الفعل، مش الواجهة.
- السطر بيوصل كرمز وقيم، مش جملة جاهزة، عشان ينقرأ صح بالعربي والإنجليزي.
- بينحفظ سنة على الأقل.

```json
{
  "id": 91,
  "at": "2026-11-24T09:42:00Z",
  "actor": { "id": 3, "name": "محمد عودة" },
  "kind": "sensitive",
  "event": "discount",
  "params": { "percent": 15, "invoice": "INV-2041" },
  "detail": "زبون دايم"
}
```

الأنواع: `sale`، `sensitive`، `stock`، `settings`، `login`.
الأحداث: `discount`، `settingsChanged`، `bulkEdit`، `damage`، `returnApproved`، `countStarted`، `login`، `shiftOpened`، `staffAdded`، `staffStopped`.

أي تغيير بالإعدادات لازم ينكتب بالسجل كـ `settingsChanged` ومعه شو تغير.

## الوحدة 3: الأصناف والتصنيفات والمواد الفعالة

القراءة لكل الأدوار. الإضافة والتعديل والاستيراد للمديرة والصيدلي بس، والكاشير بياخد 403.

### الأصناف

| الطريقة | الرابط                       | الطلب                                                                            | الرد                                            |
| ------- | ---------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------- |
| GET     | `/api/products`              | `tab`، `category`، `ingredient`، `supplier`، `sort`، `search`، `page`، `perPage` | صفحة أصناف، ومعها `meta` و`counts`              |
| GET     | `/api/products/{id}`         |                                                                                  | الصنف كامل: الدفعات، الحركات، المبيعات، البدائل |
| POST    | `/api/products`              | حقول الصنف، و`opening` اختياري                                                   | 201، الصنف                                      |
| PUT     | `/api/products/{id}`         | حقول الصنف بدون `opening`                                                        | الصنف                                           |
| POST    | `/api/products/bulk`         | `ids`، `changes`                                                                 | 204، وسطر `bulkEdit` بالسجل                     |
| POST    | `/api/products/{id}/barcode` |                                                                                  | `{ "data": { "barcode": "2000000000060" } }`    |
| GET     | `/api/products/export`       | `ids` اختياري، مفصولة بفواصل                                                     | ملف Excel                                       |
| GET     | `/api/catalog`               | `search`                                                                         | أدوية من القائمة المشتركة                       |
| GET     | `/api/suppliers/options`     |                                                                                  | `id` و`name` لكل مورد، للاختيار                 |

**الحالة بيحسبها السيرفر**، بهالترتيب:

1. ما في كمية: `out`
2. أقرب دفعة انتهت: `expired`
3. أقرب دفعة بتنتهي خلال مدة تنبيه الصلاحية من الإعدادات: `soon`
4. الكمية عند الحد الأدنى أو تحته: `low`
5. غير هيك: `ok`

والصنف الموقوف (`active = false`) بيطلع بتبويب `stopped` بس، وما بيطلع بالبيع ولا بالبدائل.

**القيم بالرد:**

- `counts`: عدد كل تبويب بعد الفلاتر التانية، عشان الأرقام فوق التبويبات تضل صح مع البحث.
- البحث بالاسم والاسم العربي، وبيفهم العربي زي ما بينكتب (أ وإ وا نفس الشي). ولو النص باركود كامل، بيلاقي الصنف.
- الترتيب: `expiry` (الأقرب انتهاء أول، والنافد آخر)، `name`، `quantity`.
- الكمية والسعر والحد الأدنى كلهم بأول وحدة (الأكبر). السيرفر بيخزن المخزون بأصغر وحدة مفعلة وبيحول.
- `cost` و`averageCost` بيرجعوا `null` للي ما إله صلاحية يشوف سعر الشراء.
- الدفعات مرتبة بالأقرب انتهاء، والأولى عليها `nextToSell = true`.
- `dailySales`: 30 رقم، من قبل 30 يوم لليوم.
- `alternatives`: الأصناف النشطة اللي إلها نفس المادة الفعالة.

شكل وحدات البيع:

```json
"units": [
  { "name": "علبة", "perParent": null, "price": 39, "enabled": true },
  { "name": "شريط", "perParent": 2, "price": 20, "enabled": true },
  { "name": "حبة", "perParent": 7, "price": 3, "enabled": false }
]
```

- أول وحدة `perParent = null` ولازم تكون مفعلة.
- كل وحدة بعدها: كم منها بالوحدة اللي فوقها، رقم صحيح أكبر من 1.
- الحد: 3 وحدات.

**قواعد الحفظ:**

- الباركود مكرر: 422 و`errors.barcode = ["taken"]`.
- `opening` بالإضافة بس: `{ "quantity", "expiry", "cost" }`. بيعمل دفعة وحركة `opening`. بعد هيك المخزون بيدخل من المشتريات.
- التعديل الجماعي: بس الحقول الموجودة بـ `changes` بتتغير. `pricePercent` بيغير سعر كل الوحدات بالنسبة، ومقرب لأغورة.
- الرمز الداخلي: EAN-13 بيبلش بـ 2، ورقم التحقق صحيح، وبينحفظ على الصنف. لو الصنف إله باركود، بيرجعه زي ما هو.

الواجهة بتقرأ الملف وبتربط الأعمدة، وبتبعت كل سطر كنص:

```json

  "name": "Strepsils Cool 24",
```

- التاريخ بيوصل `YYYY-MM-DD` لو الواجهة فهمته، وغير هيك بيوصل زي ما انكتب.

**المشاكل**، مشكلة وحدة لكل سطر، أول وحدة بتمنعه:

`nameMissing`، `priceMissing`، `priceInvalid`، `quantityInvalid`، `expiryMissing` (في كمية بدون تاريخ)، `expiryInvalid`، `expiryPast`.

و`duplicate` لما الباركود موجود. هاي مش مشكلة بتمنع: `duplicates` بالطلب بيقول لكل سطر `update` أو `skip`، والافتراضي `update` (بيحدث سعر أول وحدة).

**الاستيراد نفسه:**

- السطر اللي فيه مشكلة بيتخطى وبينعد بـ `skipped`.
- التصنيف أو المادة اللي مش موجودة بتنعمل، وبتنحسب.
- كل كمية بتصير دفعة وحركة `import`.
- السيرفر بيحفظ شو أضاف كل استيراد، عشان التراجع يشيلهم.
- كل الاستيراد بمعاملة وحدة: يا بينحفظ كله يا ولا شي.

### للسيرفر بشكل عام

أي رد ناجح بدون محتوى (204 أو 202) بيكون فاضي تماماً، والواجهة بتتعامل معه.
