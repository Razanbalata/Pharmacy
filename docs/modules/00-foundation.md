## تشغيل المشروع

```bash
npm ci
cp .env.example .env.local
npm run dev
```

ليش `npm ci` مش `npm install`؟ لأنه الأول بيثبت المكتبات بالضبط زي ما هي بملف القفل وما بيغيره. التاني ممكن يعدل ملف القفل، وهاد اللي خرّب التثبيت مرة.

بعد التشغيل افتحي:

| العنوان                        | شو بتشوفي                              |
| ------------------------------ | -------------------------------------- |
| `http://localhost:5173/`       | إطار التطبيق ولوحة التحكم (صفحة مؤقتة) |
| `http://localhost:5173/ui-kit` | كل المكونات المشتركة بمكان واحد        |

لتجربة الأدوار، من أدوات المطور بالمتصفح:

```js
localStorage.mockRole = 'cashier' // أو 'pharmacist' أو 'manager'
```

وبعدين حدّثي الصفحة.

## فحص الجودة

أمر واحد بيفحص كل شي:

```bash
npm run check
```

وهو بيشغل بالترتيب:

| الخطوة | الأمر          | شو بتفحص                         |
| ------ | -------------- | -------------------------------- |
| 1      | `format:check` | شكل الكود مرتب                   |
| 2      | `lint`         | ما في أخطاء ولا تحذيرات          |
| 3      | `lint:fsd`     | ما في طبقة بتستورد من طبقة فوقها |
| 4      | `typecheck`    | الأنواع كلها صح                  |
| 5      | `test`         | كل الاختبارات ناجحة              |
| 6      | `build`        | المشروع بينبني للنسخة النهائية   |

**قبل كل كوميت هالأمر بيشتغل لحاله.** لو فشل، الكوميت ما بيصير. الأداة اللي بتعمل هيك:

simple-git-hooks

قواعد الفحص المهمة:

- ممنوع نوع `any`.
- الاستيراد اللي للأنواع بس لازم يكون مكتوب إنه للأنواع.
- ممنوع الاستيراد الدائري.
- قواعد سهولة الوصول: كل زر إله اسم، وكل حقل إله تسمية.

## الطبقات

```
src/
  app/        ← تشغيل التطبيق والإطار والروابط
  pages/      ← صفحة لكل رابط
  widgets/    ← قطع كبيرة: القائمة الجانبية، الشريط العلوي، البحث الشامل
  features/   ← أفعال المستخدم: تبديل اللغة، تبديل المظهر
  entities/   ← أشياء العمل: الجلسة، التنبيهات
  shared/     ← أدوات عامة: الاتصال، الترجمة، المكونات
```

**القاعدة الذهبية:** كل طبقة بتستورد من اللي تحتها بس. وجوا نفس الطبقة، وحدة ما بتستورد من وحدة تانية.

**مثال حقيقي صار معنا:** الشريط العلوي فيه زر البحث، والبحث الشامل قطعة تانية. أول مرة الشريط استورد البحث مباشرة، والأداة رفضت. الحل: الشريط بياخد دالة اسمها `onOpenSearch`، والإطار بطبقة التطبيق هو اللي بيربطهم. هيك كل قطعة بتضل مستقلة.

**كل وحدة إلها باب واحد:** الملف `index.ts`. أي إشي مش مكتوب فيه، ممنوع حدا برا الوحدة يستخدمه.

كل طبقة وكل وحدة إلها ملف شرح بالعربي جواها.

## نظام التصميم والمظهر

**الألوان** جاية من نظام التصميم المنشور، ومكتوبة بملف واحد:

```
src/app/styles/tokens.css
```

كل لون إله قيمتين: نهاري وليلي. وكل لون صار إله اسم بالأنماط:

```
bg-brand  text-ink  border-border  bg-surface-100  text-danger
```

ممنوع نكتب رقم لون مباشر بالكود.

**الخطوط:** Readex Pro للعناوين والأرقام، و IBM Plex Sans Arabic للنص. الاتنين محملين جوا المشروع، فبيشتغلوا بدون نت.

**أحجام الخط** من نظام التصميم: `text-display` و`text-heading` و`text-body` و`text-small` وغيرهم.

**المظهر:** تلات خيارات: حسب الجهاز، نهاري، ليلي. الاختيار بينحفظ بالمتصفح، وبينكتب على الصفحة:

```html
<html data-theme="dark"></html>
```

**خطأ لقيناه وصلحناه:** أداة دمج الأنماط ما كانت تعرف أحجام خطوطنا، فلما يكون في `text-body` جنب لون زي `text-surface-100`، كانت تحذف اللون. زر الحذف والزر النصي طلعوا بلون غلط. علمناها أحجامنا، وضفنا اختبار:

```
src/shared/lib/cn/cn.ts
```

## اللغتين والاتجاه

- العربي هو الأساس، والإنجليزي لازم يكون إله **نفس المفاتيح بالضبط**. لو نقص مفتاح، فحص الأنواع بيفشل.
- `t('مفتاح')` مفحوص كمان: لو كتبتي مفتاح مش موجود، بيطلع خطأ قبل التشغيل.
- مع تبديل اللغة بيتغير اتجاه الصفحة كلها:

```html
<html lang="ar" dir="rtl"></html>
```

- كل الأنماط مكتوبة بالبداية والنهاية مش باليمين والشمال (مثلاً `ms-` و`end-`)، فالصفحة بتنقلب صح لحالها.

النصوص:

```
src/shared/i18n/locales/ar.ts
src/shared/i18n/locales/en.ts
```

## الاتصال بالسيرفر

**دالة وحدة** لكل الطلبات بالمشروع:

```
src/shared/api/http.ts
```

**الدخول بالكوكيز** بطريقة لارافيل:

Laravel Sanctum SPA

الجلسة محفوظة بكوكي ما بيقدر الجافاسكربت يقراه، وهاد أأمن من حفظ التوكن بالمتصفح. ومع كل طلب بيغير إشي، بنبعت كوكي الحماية بالترويسة.

**الأخطاء موحدة:** أي طلب بيفشل بيرجع `ApiError`، وفيه أسئلة جاهزة:

| السؤال              | معناه                  | شو بنعمل               |
| ------------------- | ---------------------- | ---------------------- |
| `isUnauthenticated` | مش داخل أو الجلسة خلصت | بنحوله لشاشة الدخول    |
| `isForbidden`       | دوره ما بيسمح          | بنعرض رسالة            |
| `isValidation`      | غلط بالنموذج           | بنعرض الخطأ تحت كل حقل |
| `isNetwork`         | ما وصل للسيرفر         | غالباً النت مقطوع       |

**إعادة المحاولة:** لو الخطأ من المستخدم (400 لـ 499) ما بنعيد، لأنه ما رح يتغير. لو خطأ نت أو سيرفر، بنعيد مرتين.

## السيرفر الوهمي وملف العقد

لحد ما نخلص الفرونت، في سيرفر وهمي بيشتغل جوا المتصفح:

Mock Service Worker

بيمسك الطلبات قبل ما تطلع، وبيرد ببيانات بنفس أسماء وأرقام التصميم: صيدلية الشفاء، رزان المديرة، 8 تنبيهات، 18 يوم تجربة.

**الكود ما بيعرف إنه وهمي.** لما يجهز الباك إند، بنغير سطر بملف البيئة:

```
VITE_API_MOCKS=false
```

السيرفر الوهمي بيشتغل بالتطوير والاختبارات بس، وتأكدنا إنه ما بيدخل بالنسخة النهائية.

**ملف العقد:** كل رابط بنحتاجه من الباك إند مكتوب فيه مع شكل البيانات:

```
BACKEND_CONTRACT.md
```

الروابط لهلأ:

| الطريقة | الرابط                 | شو بيرجع                             |
| ------- | ---------------------- | ------------------------------------ |
| GET     | `/sanctum/csrf-cookie` | كوكي الحماية                         |
| GET     | `/api/me`              | المستخدم الحالي ودوره وصيدليته وخطته |
| GET     | `/api/alerts/summary`  | عدد التنبيهات الجديدة                |

## الجلسة والصلاحيات

```
src/entities/session/
```

**دالة وحدة بتقرر مين بيفتح شو:** `canAccess(role, area)`. القائمة الجانبية والبحث الشامل والجرس كلهم بيسألوها، فما بيصير تناقض.

| الدور   | شو بيشوف                                                       |
| ------- | -------------------------------------------------------------- |
| المدير  | كل شي                                                          |
| الصيدلي | كل شي غير الورديات والمصاريف والموظفين والإعدادات              |
| الكاشير | لوحة التحكم، والبيع، والفواتير، والمرتجعات، والزبائن، والأصناف |

**الإخفاء بالواجهة للراحة مش للحماية.** السيرفر لازم يفحص الدور كمان بكل رابط.

**القائمة الجانبية** مكتوبة كقائمة وحدة مرتبة زي التصميم، و`navigationFor(role)` بترجعها للدور: بتشيل اللي ممنوع، وبتشيل المجموعة لو فضيت.

## هيكل التحميل

**ولا صفحة بتعرض دوامة تحميل.** بدالها في هيكل رمادي بنفس شكل الصفحة الجاية، وعليه لمعة خفيفة بتتحرك. اللي مفعّل عنده تقليل الحركة بجهازه، ما بتطلعله اللمعة.

| الشكل     | لأي صفحات                                   |
| --------- | ------------------------------------------- |
| قائمة     | عنوان، فلاتر، جدول. الافتراضي لأغلب الصفحات |
| لوحة تحكم | شريط، أربع بطاقات أرقام، رسم وقائمة         |
| تفاصيل    | قسمين وعمود جانبي. لنقطة البيع والمساعد     |
| نموذج     | حقول بعمودين. للإعدادات                     |

**وين بيطلع:**

1. **أول فتح للتطبيق:** شكل التطبيق كامل رمادي، يعني القائمة والشريط والصفحة.
2. **لما المستخدم الحالي لسا عم يتحمل:** نفس الشكل.
3. **لما تنتقلي لصفحة جديدة:** هيكل الصفحة الجاية مكان القديمة، لحد ما يتحمل كودها.
4. **جوا الصفحات:** الجدول بيعرض صفوف رمادية وقت ما البيانات عم تيجي.

أي صفحة بأي شكل محدد هون:

```
src/app/routes/skeletons.ts
```

## إطار التطبيق

```
RootLayout   ← كل الصفحات: شريط انقطاع النت والرسائل السريعة
  AppLayout  ← صفحات الداخلين: القائمة والشريط والبحث
    الصفحة
```

**القائمة الجانبية:**

- اسم الصيدلية تحت اسم المنتج.
- المجموعات زي التصميم: البيع، المخزون، المشتريات، المالية والتقارير، الإدارة.
- الصفحة الحالية ملونة.
- عدد التنبيهات الجديدة من السيرفر، وبيتحدث كل دقيقة.
- بطاقة المساعد الذكي (ما بتطلع للكاشير).
- سطر الخطة: "باقي 18 يوم"، أو "انتهت التجربة المجانية".

**الشريط العلوي:**

- زر البحث، وبيفتح البحث الشامل.
- زر "بيع جديد".
- الجرس مع عدد التنبيهات (ما بيطلع للكاشير).
- قائمة المستخدم: اسمه ودوره وصيدليته، وتبديل اللغة والمظهر.

**على الجوال:** القائمة الجانبية بتختفي، وبتنفتح من زر القائمة كنافذة جانبية من جهة البداية.

**لو المستخدم مش داخل:** بيتحول لشاشة الدخول لحاله.

**كل روابط القائمة شغالة من هلأ:** الشاشات اللي لسا ما انبنت بتفتح صفحة بتقول بأي وحدة رح تنبنى.

## الشغل بدون إنترنت

القرار: الهيكلية جاهزة هلأ، والتكملة بعد ما يخلص المشروع.

**الجاهز:**

- شريط "الاتصال مقطوع" فوق كل الصفحات، وعدد العمليات اللي بتستنى.
- صندوق الصادر: بيحفظ العمليات وبيبعتها بالترتيب لما يرجع النت. كل عملية إلها رقم ثابت، فلو انبعتت مرتين السيرفر بيرفض التكرار. لو السيرفر رفضها، بتتعلم فاشلة وبيكمل الباقي. وما بيصير إرسالين بنفس الوقت.

**الضايل:** مكتوب بالتفصيل هون:

```
src/shared/lib/offline/README.md
```

## شو تعلمنا

1. **الأداة بتحمي الهيكلية مش الذاكرة.** ما في حاجة تتذكري قواعد الطبقات، لأنه الفحص بيرفض الغلط.
2. **مصدر واحد لكل قاعدة:** العناوين بملف واحد، والصلاحيات بدالة وحدة، والألوان بملف واحد، والقائمة بقائمة وحدة. أي تعديل بمكان واحد.
3. **الواجهة بتخبي، والسيرفر بيمنع.** الصلاحيات بالواجهة للراحة بس.
4. **بنبني على عقد، مش على سيرفر.** الفرونت ما بيستنى الباك إند، وملف العقد هو قائمة شغله.
5. **الاختبار بيختبر اللي المستخدم بيشوفه:** بنلاقي العناصر باسمها اللي بينقرأ، مش بأسماء الأنماط. هيك الاختبار نفسه بيفحص سهولة الوصول.

**الوحدة الجاية:** الدخول والبداية، يعني تسجيل الدخول، وطلب الانضمام، وتفعيل الحساب، وتجهيز الصيدلية، وقائمة البداية، وصفحة طلبات الانضمام بلوحة صاحبة المنصة.
