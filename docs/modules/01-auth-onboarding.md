## الرحلة كاملة

**صيدلية جديدة:**

```
طلب انضمام  →  صاحبة المنصة بتراجع وبتوافق  →  رابط تفعيل على واتساب
     →  المالكة بتختار كلمة المرور  →  تجهيز الصيدلية  →  قائمة البداية
```

**كل يوم:**

```
تسجيل الدخول  →  المديرة والصيدلي: لوحة التحكم
               →  الكاشير: نقطة البيع
               →  صاحبة المنصة: طلبات الانضمام
```

**القرار المهم بهالوحدة:** الصيدليات ما بتعمل حساب لحالها. بتقدم طلب، وانتِ بتوافقي، وبعدها هي بتختار كلمة المرور. هيك:

- ما بتدخل إلا الصيدليات المرخصة.
- انتِ ما بتعرفي كلمة مرور حدا.
- الطريقة بتضل تزبط لما يكبر العدد.

## الشاشات

### 1. تسجيل الدخول

```
/login
src/pages/login/
src/features/auth/login/
```

- بيقبل الجوال أو البريد، والجوال بأي شكل: بمسافات، أو بأرقام عربية.
- "خليني داخل على هالجهاز" مفعل افتراضياً.
- **لو البيانات غلط:** "الجوال أو كلمة المرور مش صح". ولما يضل 3 محاولات أو أقل، بيقلها كم ضايل.
- **بعد 5 محاولات غلط:** الدخول بيتقفل 15 دقيقة.
- **بعد الدخول كل دور بيروح لمكانه:** الكاشير لنقطة البيع، وصاحبة المنصة لطلبات الانضمام، والباقي للوحة التحكم. القاعدة بمكان واحد:

```
src/entities/session/model/landing.ts
```

- لو كانت داخلة أصلاً وفتحت صفحة الدخول، بتروح لشاشتها مباشرة.
- قبل الدخول بنطلب كوكي الحماية من لارافيل.

### 2. طلب الانضمام

```
/join
src/pages/join/
src/features/join/submit-request/
```

- الحقول: اسم الصيدلية، والمالكة، والمدينة، وجوال الواتساب، ورقم الترخيص، والموافقة على الشروط.
- **المدينة** اختيار بالبحث من قائمة جاية من السيرفر، ولو مدينتها مش موجودة بتكتبها وبتضيفها.
- **الجوال** لازم يبلش بـ 059 أو 056 ويكون 10 أرقام. بنرتبه قبل ما نبعته، فبيوصل للسيرفر بدون مسافات.
- **لو الرقم إله طلب أو حساب:** الخطأ بيطلع تحت حقل الجوال بالذات.
- **بعد الإرسال:** بطاقة "وصلنا طلبك" فيها رقم الطلب وآخر 3 أرقام من الجوال، والخطوات فوق بتتقدم خطوة.

### 3. تفعيل الحساب

```
/activate/:token
src/pages/activate/
src/features/join/activate-account/
```

- الرابط بيوصل المالكة على واتساب بعد ما توافقي.
- **وقت التحميل:** هيكل رمادي بشكل النموذج.
- **الرابط صالح:** "انقبل طلب صيدلية الحكمة"، والجوال معروض ومقفول، والبريد اختياري، وكلمة المرور مع مقياس قوتها وتكرارها.
- **الرابط منتهي:** رسالة وزر "ابعتولي رابط جديد".
- **الرابط مش صحيح:** رسالة بتطلب تفتح الرابط كامل من الواتساب.
- بعد التفعيل بتدخل لحالها وبتروح لتجهيز الصيدلية.

### 4. نسيت كلمة المرور

```
/forgot-password
src/pages/forgot-password/
src/features/auth/reset-password/
```

تلات خطوات بنفس الشاشة، ومعهم مؤشر الخطوات:

1. **وين نبعت الكود:** الجوال أو البريد، وواتساب أو رسالة.
2. **الكود:** 6 أرقام. في عداد تنازلي قبل ما يقدر يطلب كود جديد. لو الكود غلط، الخطأ تحت الحقل.
3. **كلمة جديدة:** مع تكرارها، وملاحظة إنه الحفظ بيطلع كل الأجهزة التانية. بعد الحفظ رسالة سريعة وبيرجع للدخول.

ملاحظة للموظفين: الموظف اللي نسي، المديرة بتعمله كلمة جديدة من صفحة الموظفين (الوحدة 2).

### 5. تجهيز الصيدلية

```
/setup
src/pages/setup/
src/features/pharmacy/setup-pharmacy/
```

- بدون قائمة جانبية، ومعها مؤشر الخطوات على الخطوة التالتة.
- **عمود البيانات:** معبّا من طلب الانضمام: الاسم، والمدينة، والترخيص، والعنوان، والجوال، والعملة (شيكل ومقفولة).
- **عمود "كيف بدك تبدئي؟":** أربع خيارات كبطاقات:

| الخيار           | وين بيوديها                             |
| ---------------- | --------------------------------------- |
| عندي ملف Excel   | الأصناف، ومعالج الاستيراد مفتوح         |
| القائمة المشتركة | الأصناف، والقائمة المشتركة مفتوحة       |
| بيانات تجريبية   | قائمة البداية، وخطوة الأصناف معلّمة خلصت |
| بلشي فاضي        | قائمة البداية                           |

- لو حد مش داخل فتح الرابط، بيتحول للدخول.

### 6. قائمة البداية

```
/getting-started
src/pages/getting-started/
src/features/pharmacy/dismiss-onboarding/
```

- **فوق:** "أهلاً رزان، صيدلية الشفاء جاهزة تقريباً" ودائرة التقدم.
- **ست خطوات:** الخلصانة عليها علامة صح ومشطوبة، والجاية ملونة وزرها أساسي، والباقي زرها ثانوي. كل زر بيفتح شاشته.
- **على الجنب:** جربي بيعة، والاختصارات، والمساعد الذكي.
- **"خفي القائمة":** بتختفي وبتفتح لوحة التحكم.
- **المديرة بتشوفها مكان لوحة التحكم** لحد ما تخلصها أو تخفيها. القاعدة هون:

```
src/app/routes/DashboardEntry.tsx
```

### 7. طلبات الانضمام (لوحة صاحبة المنصة)

```
/platform/requests
src/pages/platform-requests/
src/features/platform/review-join-request/
```

- **الفلاتر:** جديدة، وانقبلت وما تفعلت، ومفعلة، ومرفوضة، ومع كل وحدة عددها.
- **القائمة:** اسم الصيدلية والمالكة والمدينة والجوال وحالة الطلب، وأول طلب محدد تلقائياً.
- **التفاصيل:** كل البيانات وصورة الترخيص وتنبيه "اتصلي قبل ما توافقي".
- **قبول:** رسالة سريعة، والطلب بينتقل لـ"انقبلت وما تفعلت"، والسيرفر بيبعت رابط التفعيل.
- **رفض:** نافذة بتطلب السبب، وزر الرفض معطل لحد ما تكتبي سبب. السبب بيوصل للمالكة.
- **اتصال:** بيفتح الاتصال على الجوال مباشرة.
- **إضافة صيدلية بإيدي:** نافذة جانبية بنفس حقول طلب الانضمام، والصيدلية بتنضاف منقبلة.

## النماذج: كيف بتشتغل

كل نموذج بالمشروع بنفس الطريقة:

**1. القواعد مكتوبة بـ Zod، والرسالة مفتاح ترجمة:**

```ts
const schema = z.object({
  phone: z.string().refine(isMobileNumber, 'validation.phone'),
})
```

**2. React Hook Form بيربط القواعد بالحقول:**

```ts
const form = useForm({ resolver: zodResolver(schema) })
```

**3. الحقل بيمر من `Field`، والخطأ بيتحول لنص:**

```tsx
<Field label={t('auth.join.phone')} error={errorText(formState.errors.phone?.message)}>
  {(field) => <Input {...field} {...register('phone')} />}
</Field>
```

**4. أخطاء السيرفر بتنحط تحت حقلها:** السيرفر بيرجع كود قصير مثل `taken`، وإحنا بنحوله لرسالة:

```ts
applyServerErrors(error, form.setError, { taken: 'validation.phoneTaken' })
```

**ليش الرسالة مفتاح مش نص؟** عشان تتبدل مع اللغة، وعشان فحص الأنواع بيتأكد إنه المفتاح موجود.

## الإطارات الجديدة

```
RootLayout        ← كل الصفحات
  AppLayout       ← موظفين الصيدلية
  PlatformLayout  ← صاحبة المنصة بس
  RequireAuth     ← للداخلين بدون قائمة، زي تجهيز الصيدلية
  صفحات عامة      ← الدخول والانضمام والتفعيل ونسيت كلمة المرور
```

**الحماية من الجهتين:**

- موظف صيدلية فتح رابط المنصة: بيرجع لشاشته.
- صاحبة المنصة فتحت رابط صيدلية: بتروح لطلبات الانضمام.
- حد مش داخل فتح أي صفحة داخلية: بيروح للدخول.

صار إله **ذاكرة**:

```
src/app/mocks/db.ts
```

يعني لما توافقي على طلب، بيضل موافق عليه وانتِ بتتنقلي بالتطبيق. ومع تحديث الصفحة بيرجع كل شي زي التصميم. وكل اختبار بيبلش من نفس البداية.

بيانات الطلبات من التصميم: صيدلية الرحمة والوفاء وابن سينا (جديدة)، والحكمة (انقبلت)، والشفاء (مفعلة)، والمدينة (مرفوضة).

كلها مكتوبة بالتفصيل بملف العقد، وفي ملخص هون:

| المجموعة    | الروابط                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| الدخول      | `POST /api/login`، `POST /api/logout`                                                                        |
| كلمة المرور | `POST /api/password/otp`، `POST /api/password/verify`، `POST /api/password/reset`                            |
| الانضمام    | `POST /api/join-requests`                                                                                    |
| التفعيل     | `GET /api/activation/{token}`، `POST /api/activation/{token}`، `POST /api/activation/{token}/resend`         |
| الصيدلية    | `GET /api/pharmacy`، `PUT /api/pharmacy`، `GET /api/cities`                                                  |
| البداية     | `POST /api/onboarding/start`، `GET /api/onboarding`، `POST /api/onboarding/dismiss`                          |
| المنصة      | `GET /api/platform/join-requests`، `POST /api/platform/join-requests`، `.../{id}/approve`، `.../{id}/reject` |

**قواعد لازم الباك إند يلتزم فيها:**

- 5 محاولات دخول غلط بتقفل الدخول 15 دقيقة.
- رابط إرسال الكود بيرد نفس الرد سواء الرقم مسجل أو لا.
- رابط التفعيل لمرة وحدة و48 ساعة.
- التجربة بتبلش من التفعيل.
- روابط المنصة لصاحبة المنصة بس.

## شو تعلمنا

1. **ابنِ القرار بالكود مش بالشاشة:** وين بيروح كل دور، ومين بيشوف قائمة البداية. كل قرار إله دالة وحدة، والشاشات بتسألها.
2. **الخطأ تحت حقله:** المستخدم ما بيقرأ رسالة عامة فوق. لو الجوال مكرر، الخطأ تحت الجوال.
3. **الحالات كلها، مش الحالة الحلوة بس:** التحميل، والرابط المنتهي، والرابط الغلط، والمحاولات الكتير، وغير الداخل. كل وحدة إلها شكل.
4. **الاختبار اللي بيمشي زي المستخدم بيلاقي أخطاء حقيقية:** خطأ الرد الفاضي ما كان رح يبين بالعين إلا مع الباك إند.
5. **الأمان مش إضافة:** ما بنعرف كلمات المرور، والقفل بعد المحاولات، والرد الموحد بالاسترجاع، ومسح البيانات عند الخروج.

**الوحدة الجاية:** الموظفون والإعدادات.
